# scripts/

Run everything from the repository root, e.g. `python scripts/rag/try_expert_rag.py --seed-silver`. Inside the dev
container `PYTHONPATH=/workspace/backend` is already set (scripts import `app.*`); elsewhere set it.
Scripts in a folder import their helpers by plain module name (`rag_common`, `make_fixtures`), so a
folder is self-contained.

| Folder | Responsibility | Scripts (in pipeline order) |
|---|---|---|
| `db/` | Database access and the experiment schemas | `psql.sh` (psql shell, `overview`); `load_chips_pg` + `chips_schema.sql` (experiment chip units into the schema `chips_eval`; it refuses `chips`, where the web application ingests approved answers), `chips_backup` (back up, verify, empty and restore the tables of `chips`) |
| `rag/` | Try the expert-notes RAG and evaluate it | expert notes: `eval_expert_units`, `eval_expert_generation`, `judge_generations` (clinician rubric, LLM or human judges), `chat_expert` (human chat + ratings); shared `rag_common`; chip units (notes/new-chips-knowledge.md): `chip_retrieval`, `eval_chip_units`, `eval_chip_generation` (chips vs the B1 baseline, same questions and claims); `try_expert_rag`, `eval_scale_retrieval` (retrieval at 1-32 experts per vignette on the local schema `chips_scale`; `--order` changes which experts join first; `--freeze-queries <snapshot dir>` freezes its questions and vectors next to the scale snapshot for `tests/integration/test_scale_regression.py`, run with `uv run pytest -m scale`, rebaseline with `UPDATE_SCALE_BASELINE=1`), `eval_style_diversity` (how alike the experts write, raw vs proofread) (the `expert-knowledge-rag` package over Postgres: retrieval + generation for labelled questions, per vignette (several experts) and patient texts, saved for human grading and `judge_generations`; `--seed-silver` builds schema `chips_silver`) |
| `elicitation/` | Elicitation documents: test fixtures and schema | `make_fixtures` (synthetic vignettes and answers, see `notes/fixtures.md`), `export_schema`; chips test (notes/new-chips-knowledge.md, data in `data/fixtures_chips`): `chips_schema`, `make_chip_fixtures`, `classify_sentence_targets`, `chip_findings` (pure; tests in `tests/scripts/test_chip_findings.py`), `build_chip_units`; `llm_clients`, `prompt_loader` and `leak_terms` are helpers of `make_fixtures` (generation lives here, not in `backend/`); local scale fixture (gitignored `data/`): `make_scale_fixtures` (`--stage seed|vignettes|answers|proofread|build`: 24 vignettes, 32 experts: 3-20 by one local model, 21-32 by gpt-oss, mistral-small and qwen from the persona files in `prompts/expert_personas/`; `proofread` runs every answer through the web application's proofreading; `build --proofread` loads the schema `chips_scale`, plain `build` the raw answers into `chips_scale_raw`); `export_scale_answers` writes every answer (raw and proofread, with highlights, claims and who wrote them) to one JSON file, `data/exports/scale_answers.json`; `eval_enhance` (the proofreading's fuller-sentences pass, `Answer_enhance` v1 vs v2 under the old and new reply checks, on the scale fixture: `--calibrate` needs no model, a run writes blinded blocks for Claude judges, `--aggregate` reads their grades) |

Rule of thumb: production logic belongs in `backend/app/`; a script only wires it together or
holds throwaway/example code (like the Reddit post reader).
